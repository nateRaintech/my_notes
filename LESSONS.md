# LESSONS.md — Accumulated Project Memory

This is autodev's **compounding memory**. Every session is a cold start with no recollection of previous runs — this file is how hard-won knowledge survives across sessions so the framework gets *smarter* over time instead of relearning (or repeating) the same mistakes.

**Read this at session startup. Append to it at wrap-up when you learn something reusable.** Unlike `autodev_log.md` (local-only, per-session noise), `LESSONS.md` is committed and shared — keep it concise and high-signal.

## What belongs here

- **Conventions** — project-specific patterns not obvious from a quick read (naming, layering, how config/secrets are loaded, where to put X).
- **Gotchas** — non-obvious traps: flaky tests, slow steps to avoid, environment quirks, commands that need special flags.
- **Anti-patterns** — approaches that wasted a session or got bounced. Record what *not* to do and why, so no future session retries it.

## What does NOT belong here

- Per-session status (that's `autodev_log.md`).
- Things already documented in `CLAUDE.md` or `github.md` — link to those instead of duplicating.
- Speculation. Only record something once a session has actually confirmed it.

## Format

One dated bullet per lesson, newest at the top of its section. Keep each to a sentence or two.

```
- YYYY-MM-DD — <the lesson>. (why it matters / what triggered it)
```

## Gotchas

- 2026-05-23 — **Non-ASCII characters (em-dash `—`, arrows `→`, curly quotes `"" ''`) in `gh issue create` / `gh pr create` titles+bodies passed via the Bash tool (git-bash) on Windows turn into MOJIBAKE.** A `--body` with an em-dash rendered as `a-EUR-"` garbage on the live issue, requiring a `gh issue edit` to fix. Use **ASCII** in gh issue/PR titles+bodies from the Bash tool: `->` not `→`, `--` not `—`, straight quotes not curly. Git **commit messages are fine** (git stores UTF-8 natively); this is specifically the `gh` CLI argument path through git-bash on this machine. (issue #43 / PR #44.)
- 2026-05-23 — **The `pytest -q` summary line ("N passed in Xs") does NOT surface through the git-bash pipe on this machine** (only the dot-progress lines come through; `Select-String`/`grep` for "passed" returns nothing). To read the count, run pytest from the **PowerShell tool** capturing to a variable: `$out = & "...python.exe" -m pytest 2>&1 | Out-String; ($out -split "\`n" | Where-Object {$_ -match "passed|failed|error"} | Select-Object -Last 1)` then check `$LASTEXITCODE`. Or trust the exit code (0 = green) plus the dot/F/s/E counts. (Confirmed again #43/#44.)
- 2026-05-23 — **Do NOT use PowerShell here-string syntax (`@'...'@`) when committing via the Bash tool (git-bash) — it is not a here-string in bash and the literal `@` leaks into the commit message.** A `git commit -m @'...subject...'@` this session produced subject `@ autodev: record lesson…` with a trailing `@` in the body; since it was already pushed, autodev Rule 3 (no `--amend`/force-push on pushed commits) meant it had to be left malformed. From the **Bash tool**, write multi-line commit messages with a bash heredoc — `git commit -m "$(cat <<'EOF'` … `EOF`<br>`)"` (the pattern `github.md` already shows for `gh pr create`) — or a single `-m "subject"`. The PowerShell `@'...'@` form is only valid in the **PowerShell tool**.
- 2026-05-22 — **Record/commit a `LESSONS.md` lesson at wrap-up *after* the PR actually merges (the Priority 1 merge step), NOT when moving the item to In Review.** A prior session committed the note-list lesson to `main` referencing "(#35/#36)" while PR #36 was still open — so at the next cold start `main`'s HEAD was a lesson commit that *looked* like the PR had merged, while `board_snapshot.md` and the live board both correctly showed #35 still In Review. Reconciling that contradiction (live PR/branch/merge-commit checks) burned budget before any real work. The autodev.md wrap-up sequence already implies this ordering (lessons are step 2 of *that* session's wrap-up, but the merge happens in a *later* session's Priority 1); don't pre-record a lesson as if the merge already happened. The lesson text was accurate — only its timing created the drift.
- 2026-05-22 — **`QSplitter` has `setStretchFactor(index, n)` but NO `stretchFactor()` getter.** `setStretchFactor` works by writing the factor onto the *child widget's* size policy, so to assert stretch behavior in a test, read `splitter.widget(i).sizePolicy().horizontalStretch()` — calling `splitter.stretchFactor(i)` raises `AttributeError: 'QSplitter' object has no attribute 'stretchFactor'`. (Cost a test-failure cycle building the M3 3-pane layout, #23 / PR #24.)
- 2026-05-22 — **Bare `python` / `pytest` / `ruff` can resolve to the WRONG conda env on this machine.** This session, `python` on PATH pointed at the `Office_MCP` env (no `sqlcipher3`/`argon2-cffi`), so `pytest` died with `ModuleNotFoundError: No module named 'sqlcipher3'` — the traceback showed `...\envs\Office_MCP\Lib\...`, not playground. Fix: always invoke the project's interpreter by the **full path** CLAUDE.md lists under *Environment paths*: `C:\Users\Nate\anaconda3\envs\playground\python.exe -m pytest` (and `-m ruff check .`). The active env on PATH is inconsistent across sessions (some prior sessions' bare `pytest`/`pip` happened to hit playground), so don't trust bare commands — use the full path.
- 2026-05-21 (updated 2026-05-22) — Qt/PySide6 tests guard with `pytest.importorskip("PySide6")` and run headless via `os.environ.setdefault("QT_QPA_PLATFORM", "offscreen")` set *before* any Qt import; the guarded imports need `# noqa: E402` (ruff `E4` selects E402). **`importorskip` only guards the *import*** — once PySide6 is actually installed (as it now is in CI, see Conventions), a *missing Qt system lib* makes `QApplication()` abort the process (uncatchable — not a Python exception, not a skip), so the apt libs are mandatory, not optional. ## Anti-patterns

- Seed lesson — **Do not write "editorial-pin" tests** that assert a doc/markdown list matches a code constant, AST-presence checks, or set-identity between prose and code. They never catch real bugs; they only fire on intentional human edits, creating a maintenance tax. (This is encoded as a hard rule in `autodev.md` → Priority 5B "Prohibited test patterns"; recorded here so the reasoning travels with the project. If cross-file drift ever causes a *real* bug, fix it with one CI script, not per-pair tests.)
