# LESSONS.md — Accumulated Project Memory

This is autodev's **compounding memory**. Every session is a cold start with no recollection of previous runs — this file is how hard-won knowledge survives across sessions so the framework gets *smarter* over time instead of relearning (or repeating) the same mistakes.

**Read this at session startup. Append to it at wrap-up when you learn something reusable.** Unlike `autodev_log.md` (local-only, per-session noise), `LESSONS.md` is committed and shared — keep it concise and high-signal.

## What belongs here

- **Conventions** — project-specific patterns not obvious from a quick read (naming, layering, how config/secrets are loaded, where to put X).
- **Gotchas** — non-obvious traps: flaky tests, slow steps to avoid, environment quirks, commands that need special flags.
- **Anti-patterns** — approaches that wasted a session or got bounced. Record what *not* to do and why, so no future session retries it.

## What does NOT belong here

- Per-session status (that's `autodev_log.md`).
- Things already documented in `CLAUDE.md` or `github.md` — link to those instead of duplicating.
- Speculation. Only record something once a session has actually confirmed it.

## Format

One dated bullet per lesson, newest at the top of its section. Keep each to a sentence or two.

```
- YYYY-MM-DD — <the lesson>. (why it matters / what triggered it)
```

## Conventions

- 2026-05-22 — **`ui/main_window.py`'s `MainWindow` is the app's 3-pane shell: a horizontal `QSplitter` (`self.splitter`) holding three panes exposed as typed attributes** — `self.notebook_tree` (`QTreeWidget`, the notebooks/tags tree), `self.note_list` (`QListWidget`), and `self.editor` (`QTextEdit`, a placeholder). Later M3/M4 UI capabilities **populate these named panes rather than rebuilding the layout**: the Markdown-editor capability replaces `editor`, note-list/auto-save fills `note_list`, the tags capability extends `notebook_tree`, and the M4 unlock flow feeds them from `core.repository.Repository` over the keyed `Vault.connection`. Panes are non-collapsible (`setChildrenCollapsible(False)` + per-pane minimum widths, so a drag resizes but never zeroes a pane), default sizes `(220, 300, 480)` favor the editor, and the editor is the only pane that stretches on window resize. The shell carries **no data binding yet — by design** (the panes start empty). UI-layer only; `core/` stays Qt-free. (issue #23 / PR #24.)
- 2026-05-22 — **`core/repository.py` is the typed CRUD data-access layer; it takes a DB-API *connection*, not the `Vault`.** Like `schema.migrate(conn)`, `Repository(connection)` accepts the keyed `Vault.connection` in the app but an in-memory `sqlcipher3.connect(":memory:")` (migrated, `PRAGMA foreign_keys = ON`) in tests — so it runs the real SQLite/FTS5 build with no Argon2 cost and `core/` stays Qt-free; idle-lock/`touch()` stay the vault+UI's concern. Returns **frozen** `Note`/`Notebook` value objects; `get_*` → `None` when absent, `delete_*` → `bool`, `update_*` bump `updated_at`, return the refreshed object, and raise `NotFoundError` (← `RepositoryError`) on a missing id. Partial updates use a module `_UNSET` sentinel so `notebook_id=None`/`parent_id=None` (re-root) is distinct from "field not passed". Writes touch `notes`/`notebooks` **only** — the schema's FTS triggers keep `notes_fts` in sync (so search, M4, needs no repo change) and the vault's `foreign_keys = ON` makes `delete_notebook` cascade to child notebooks + orphan its notes to the root (`notebook_id` → NULL). Stores `title`/`body` **verbatim** — Markdown title derivation stays in `core.text.derive_title`. `list_notes` orders most-recently-updated first with an `id DESC` tiebreaker (deterministic despite `datetime('now')`'s 1-second resolution — so tests never depend on sub-second timing). (issue #21 / PR #22.)
- 2026-05-22 — **Completing a milestone has THREE parts, not one: check the boxes in `ROADMAP.md`, *and* move the block to "Completed milestones" with `status: done (completed <date>)`, *and* close the matching GitHub Milestone.** autodev.md's wrap-up only mentions editing `ROADMAP.md`, so prior sessions left the GitHub Milestones open even after marking the roadmap done — M1's GitHub Milestone was still `open` when M2 finished. The roadmap explicitly says "**GitHub Milestones mirror this file**", so an open GitHub Milestone with 0 open / N closed issues is mirror drift. Close it with `gh api -X PATCH repos/nateRaintech/my_notes/milestones/<number> -f state=closed` (there is no `gh milestone` subcommand). Find the number via `gh api repos/.../milestones`. (M2 completion, issue #19 / PR #20.)
- 2026-05-22 — **The vault schema lives in `core/schema.py`: a forward-only `migrate(conn)` runner keyed off `PRAGMA user_version`, called on every open.** `migrate` reads `user_version`, applies each newer `(version, DDL)` in the ordered `_MIGRATIONS` tuple, bumps `user_version`, commits — **idempotent**, so `Vault.create` calls it on a fresh DB and `Vault.unlock` calls it on every reopen (no-op when already at `SCHEMA_VERSION`). Append migrations + bump `SCHEMA_VERSION`; never edit/reorder a shipped one (field vaults already applied it). `migrate` takes any DB-API connection (no vault/sqlcipher import), so it unit-tests against an in-memory `sqlcipher3.dbapi2.connect(":memory:")` — **and FTS5 *is* compiled into the `sqlcipher3` wheel** (no extra build flags). `notes_fts` is an **external-content** FTS5 table (`content='notes', content_rowid='id'`) kept in sync by the standard `notes_ai`/`notes_ad`/`notes_au` triggers, so callers write to `notes` only and search stays correct. **Gotcha: SQLite foreign keys are OFF by default per-connection** — `ON DELETE CASCADE`/`SET NULL` are dead DDL unless the connection runs `PRAGMA foreign_keys = ON`, so the vault sets it right after keying in *both* `create` and `unlock`. In `unlock`, the migrate step is kept *outside* the page-1 `try/except` that maps `DatabaseError → InvalidPassword`, so a real migration failure on a valid key is never misreported as a wrong password. (issue #19 / PR #20.)
- 2026-05-22 — **Vault auto-lock lives in `core/vault.py`: in-place key wipe + an injectable-clock idle policy, both Qt-free.** The derived key is stored as a `bytearray` and zeroed in place on `lock()` (module helper `_wipe` does `buf[:] = b"\x00" * len(buf)`, mutating the *same* object so any held reference sees zeros). This is **best-effort** — CPython copies outside our control (the immutable `bytes` from `derive_key`, the hex string handed to `PRAGMA key`, SQLCipher's own in-memory key) can't be zeroed, so don't claim the key is fully scrubbed; the docstring says as much. Idle auto-lock is exposed as **pure policy** the UI drives: construct `Vault(path, idle_timeout=<secs|None>, clock=time.monotonic)` (also kwargs on `Vault.create`), `touch()` records activity (accessing `.connection` auto-touches, so DB use defers the lock), `is_idle_expired()` and `lock_if_idle() -> bool`. The UI calls `lock_if_idle()` from a `QTimer` tick so `core/` still imports no Qt; tests inject a `FakeClock` (callable returning a controllable value, `.advance(secs)`) to drive time without sleeping. `idle_timeout` is a public attribute (M5 settings can retune a live vault); default `None` = disabled; a locked vault is never idle-expired. (issue #17 / PR #18.)
- 2026-05-22 — **`core/vault.py` is the SQLCipher vault lifecycle; the Argon2 salt lives in a plaintext sidecar.** Unlocking re-derives the key, which needs the salt + `KdfParams` — but the salt is needed *before* the encrypted DB can be opened (chicken-and-egg), so it can't live inside the file it decrypts. The salt is **non-secret**, so it's persisted in `<vault>.meta` (JSON: format version, salt hex, KDF params) next to the vault, mirroring KeePass's unencrypted KDBX header (encapsulated behind the `Vault` API so a future single-file embedded header can replace it). Open with the raw-hex key (`PRAGMA key = "x'<64 hex>'"` from `derive_key(...).hex()`), then **force a page-1 read** (`SELECT count(*) FROM sqlite_master`) to validate: a wrong/absent key raises `sqlcipher3.DatabaseError` there, *before* any row — catch it and raise `InvalidPassword` (no partial read). **Two guards are load-bearing:** `create()` must refuse to clobber an existing file, and `unlock()` must refuse a *missing* file — `sqlcipher.connect(path)` silently **creates** a new empty DB for a missing path, so without the existence check a wrong path would "succeed" with any password. `sqlcipher3>=0.6.2` now installs in CI (manylinux `cp312` wheel on `ubuntu-latest`, confirmed green — PR #16). Schema/migrations and idle auto-lock + secure key wiping are the *next* M2 capabilities, deliberately not in this module. (issue #15 / PR #16.)
- 2026-05-22 — **Argon2id KDF lives in `core/crypto.py`; derive raw key bytes with the *low-level* API.** Use `argon2.low_level.hash_secret_raw(secret=pw.encode("utf-8"), salt=..., hash_len=32, type=Type.ID)` — NOT the high-level `argon2.PasswordHasher`, which emits encoded *verification* hashes, not raw key material. `derive_key()` returns 32 raw bytes; `core/vault.py` will hand `key.hex()` to SQLCipher as the raw-hex key (ties into the SQLCipher bullet below). Cost is tunable via the frozen `KdfParams` dataclass (`memory_cost` is in **KiB**), defaults at/above the OWASP floor (64 MiB / t=3 / p=4) — store the params per-vault so unlock re-derives identically. `derive_key` is a **total function over its byte inputs**: password policy (non-empty, strength) is the unlock dialog's job, not the KDF's. argon2 rejects salts < 8 bytes (we generate 16). `argon2-cffi` is now installed in CI (a dep enters CI only once a real test imports it). (issue #13 / PR #14.)
- 2026-05-22 — **SQLCipher storage uses the `sqlcipher3` package (`>=0.6.2`), NOT `sqlcipher3-binary`.** The M2 spike (#11) found `sqlcipher3-binary` ships **Linux-only manylinux wheels** (through 0.6.0) — `pip install sqlcipher3-binary` fails on the Windows ship target with "Could not find a version that satisfies the requirement … (from versions: none)". The sibling package **`sqlcipher3` >= 0.6.2** publishes prebuilt **Windows** wheels (`cp312-cp312-win_amd64`) and links **SQLCipher 4.12.0 community**. Open with `from sqlcipher3 import dbapi2 as sqlite`, then `PRAGMA key` before the first query; hand it the Argon2id key as a **raw hex key** (`PRAGMA key = "x'<64 hex>'"`) so SQLCipher skips its own KDF (crypto.py owns the KDF). A wrong/absent key fails on first DB access with `DatabaseError: file is not a database` — clean, no partial read (SQLCipher logs `hmac check failed for pgno=1` to stderr on those, which is the page HMAC integrity check working, not a bug). A PyInstaller `--onefile` build opens an encrypted DB with **no `--hidden-import`/`--collect-binaries` flags** — the bundled hooks pick up the extension + DLL. `requirements.txt` + `CLAUDE.md` updated to match; repro in `spikes/sqlcipher_windows/`. **The biggest project risk is resolved — the AES-GCM fallback is NOT needed.** (issue #11.)
- 2026-05-22 — **CI runs the full suite headless, including Qt.** `.github/workflows/ci.yml` installs `PySide6` plus the apt libs `libegl1 libgl1 libxkbcommon0 libdbus-1-3` and sets `QT_QPA_PLATFORM=offscreen`, so `tests/test_app_launch.py` actually runs (not skips) on `ubuntu-latest` — confirmed green (PR #8, run in 26s). The Test step is now plain `pytest -q`; the old exit-5 "no tests collected" crutch is gone, which is safe because `tests/test_text.py` provides real collected tests. `sqlcipher3-binary`/`argon2-cffi` are still **not** installed in CI — keep them out until the M2 SQLCipher spike. (issue #7 / PR #8.)
- 2026-05-21 — **Real (CI-running) tests target the pure-Python `core/` layer with no `importorskip`** — they execute in CI even though PySide6 isn't installed, so `pytest` exits 0 on real assertions instead of relying on the exit-5 "no tests collected" crutch. Qt-dependent tests stay `importorskip`-guarded smoke tests. The first such test is `tests/test_text.py` against `core/text.derive_title`. (issue #3 / PR #4.)
- 2026-05-21 — Entry point is `app.py` (a `main()` that builds the `QApplication`, shows `MainWindow`, runs the event loop); Qt-facing code lives in `ui/` (`ui/main_window.py` holds `MainWindow`). `core/` must never import Qt. (Established with M1 "app launches", issue #1 / PR #2.)

## Gotchas

- 2026-05-22 — **`QSplitter` has `setStretchFactor(index, n)` but NO `stretchFactor()` getter.** `setStretchFactor` works by writing the factor onto the *child widget's* size policy, so to assert stretch behavior in a test, read `splitter.widget(i).sizePolicy().horizontalStretch()` — calling `splitter.stretchFactor(i)` raises `AttributeError: 'QSplitter' object has no attribute 'stretchFactor'`. (Cost a test-failure cycle building the M3 3-pane layout, #23 / PR #24.)
- 2026-05-22 — **Bare `python` / `pytest` / `ruff` can resolve to the WRONG conda env on this machine.** This session, `python` on PATH pointed at the `Office_MCP` env (no `sqlcipher3`/`argon2-cffi`), so `pytest` died with `ModuleNotFoundError: No module named 'sqlcipher3'` — the traceback showed `...\envs\Office_MCP\Lib\...`, not playground. Fix: always invoke the project's interpreter by the **full path** CLAUDE.md lists under *Environment paths*: `C:\Users\Nate\anaconda3\envs\playground\python.exe -m pytest` (and `-m ruff check .`). The active env on PATH is inconsistent across sessions (some prior sessions' bare `pytest`/`pip` happened to hit playground), so don't trust bare commands — use the full path.
- 2026-05-21 (updated 2026-05-22) — Qt/PySide6 tests guard with `pytest.importorskip("PySide6")` and run headless via `os.environ.setdefault("QT_QPA_PLATFORM", "offscreen")` set *before* any Qt import; the guarded imports need `# noqa: E402` (ruff `E4` selects E402). **`importorskip` only guards the *import*** — once PySide6 is actually installed (as it now is in CI, see Conventions), a *missing Qt system lib* makes `QApplication()` abort the process (uncatchable — not a Python exception, not a skip), so the apt libs are mandatory, not optional. The old exit-5 = pass crutch is retired now that a real collected test exists. PySide6 6.11.1 installs cleanly on Windows and on `ubuntu-latest` CI. (issue #1 / PR #2; CI wired in #7 / #8.)
- 2026-05-21 — The GitHub Project board is **user-owned** (`nateRaintech`), not org-owned. `autodev.py`'s board query uses `user(login: ...)`; the stock template uses `organization(...)`. If board fetches start returning 0 items / "fetch failed", check this first. (Project #6, IDs in `CLAUDE.md`.)
- 2026-05-21 — `gh` is **not on PowerShell's PATH**; it lives at `C:\Users\Nate\bin\gh.exe`. The runner and docs call it by full path. From the Bash tool (git-bash) `gh` does resolve on PATH.

## Anti-patterns

- Seed lesson — **Do not write "editorial-pin" tests** that assert a doc/markdown list matches a code constant, AST-presence checks, or set-identity between prose and code. They never catch real bugs; they only fire on intentional human edits, creating a maintenance tax. (This is encoded as a hard rule in `autodev.md` → Priority 5B "Prohibited test patterns"; recorded here so the reasoning travels with the project. If cross-file drift ever causes a *real* bug, fix it with one CI script, not per-pair tests.)
