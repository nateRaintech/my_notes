# LESSONS.md — Accumulated Project Memory

This is autodev's **compounding memory**. Every session is a cold start with no recollection of previous runs — this file is how hard-won knowledge survives across sessions so the framework gets *smarter* over time instead of relearning (or repeating) the same mistakes.

**Read this at session startup. Append to it at wrap-up when you learn something reusable.** Unlike `autodev_log.md` (local-only, per-session noise), `LESSONS.md` is committed and shared — keep it concise and high-signal.

## What belongs here

- **Conventions** — project-specific patterns not obvious from a quick read (naming, layering, how config/secrets are loaded, where to put X).
- **Gotchas** — non-obvious traps: flaky tests, slow steps to avoid, environment quirks, commands that need special flags.
- **Anti-patterns** — approaches that wasted a session or got bounced. Record what *not* to do and why, so no future session retries it.

## What does NOT belong here

- Per-session status (that's `autodev_log.md`).
- Things already documented in `CLAUDE.md` or `github.md` — link to those instead of duplicating.
- Speculation. Only record something once a session has actually confirmed it.

## Format

One dated bullet per lesson, newest at the top of its section. Keep each to a sentence or two.

```
- YYYY-MM-DD — <the lesson>. (why it matters / what triggered it)
```

- 2026-05-22 — **Full-text search is `core/repository.py`'s `search_notes(query, *, limit=None) -> list[Note]` — an FTS5 query layer over the schema's existing external-content `notes_fts` index, no schema change.** It JOINs `notes_fts` back to `notes` on `notes.id = notes_fts.rowid` and orders by `notes_fts.rank` (FTS5 bm25; `ORDER BY rank` ascending puts the most-relevant match first), returning frozen `Note`s like `list_notes`. **Gotcha that drives the whole design: a search box's raw text must NOT be handed to `MATCH` directly** — FTS5 parses its argument as a *query language*, so bare metacharacters (`" * : ^ - ( )`) and the uppercase `AND`/`OR`/`NOT` keywords either change the meaning or raise `sqlcipher3.OperationalError` (fts5: syntax error). - 2026-05-22 — **The vault schema lives in `core/schema.py`: a forward-only `migrate(conn)` runner keyed off `PRAGMA user_version`, called on every open.** `migrate` reads `user_version`, applies each newer `(version, DDL)` in the ordered `_MIGRATIONS` tuple, bumps `user_version`, commits — **idempotent**, so `Vault.create` calls it on a fresh DB and `Vault.unlock` calls it on every reopen (no-op when already at `SCHEMA_VERSION`). - 2026-05-22 — **Vault auto-lock lives in `core/vault.py`: in-place key wipe + an injectable-clock idle policy, both Qt-free.** The derived key is stored as a `bytearray` and zeroed in place on `lock()` (module helper `_wipe` does `buf[:] = b"\x00" * len(buf)`, mutating the *same* object so any held reference sees zeros). This is **best-effort** — CPython copies outside our control (the immutable `bytes` from `derive_key`, the hex string handed to `PRAGMA key`, SQLCipher's own in-memory key) can't be zeroed, so don't claim the key is fully scrubbed; the docstring says as much. Idle auto-lock is exposed as **pure policy** the UI drives: construct `Vault(path, idle_timeout=<secs|None>, clock=time.monotonic)` (also kwargs on `Vault.create`), `touch()` records activity (accessing `.connection` auto-touches, so DB use defers the lock), `is_idle_expired()` and `lock_if_idle() -> bool`. - 2026-05-22 — **`core/vault.py` is the SQLCipher vault lifecycle; the Argon2 salt lives in a plaintext sidecar.** Unlocking re-derives the key, which needs the salt + `KdfParams` — but the salt is needed *before* the encrypted DB can be opened (chicken-and-egg), so it can't live inside the file it decrypts. The salt is **non-secret**, so it's persisted in `<vault>.meta` (JSON: format version, salt hex, KDF params) next to the vault, mirroring KeePass's unencrypted KDBX header (encapsulated behind the `Vault` API so a future single-file embedded header can replace it). Open with the raw-hex key (`PRAGMA key = "x'<64 hex>'"` from `derive_key(...).hex()`), then **force a page-1 read** (`SELECT count(*) FROM sqlite_master`) to validate: a wrong/absent key raises `sqlcipher3.DatabaseError` there, *before* any row — catch it and raise `InvalidPassword` (no partial read). **Two guards are load-bearing:** `create()` must refuse to clobber an existing file, and `unlock()` must refuse a *missing* file — `sqlcipher.connect(path)` silently **creates** a new empty DB for a missing path, so without the existence check a wrong path would "succeed" with any password. `sqlcipher3>=0.6.2` now installs in CI (manylinux `cp312` wheel on `ubuntu-latest`, confirmed green — PR #16). Schema/migrations and idle auto-lock + secure key wiping are the *next* M2 capabilities, deliberately not in this module. (issue #15 / PR #16.)
- 2026-05-22 — **Argon2id KDF lives in `core/crypto.py`; derive raw key bytes with the *low-level* API.** Use `argon2.low_level.hash_secret_raw(secret=pw.encode("utf-8"), salt=..., hash_len=32, type=Type.ID)` — NOT the high-level `argon2.PasswordHasher`, which emits encoded *verification* hashes, not raw key material. `derive_key()` returns 32 raw bytes; `core/vault.py` will hand `key.hex()` to SQLCipher as the raw-hex key (ties into the SQLCipher bullet below). Cost is tunable via the frozen `KdfParams` dataclass (`memory_cost` is in **KiB**), defaults at/above the OWASP floor (64 MiB / t=3 / p=4) — store the params per-vault so unlock re-derives identically. `derive_key` is a **total function over its byte inputs**: password policy (non-empty, strength) is the unlock dialog's job, not the KDF's. argon2 rejects salts < 8 bytes (we generate 16). `argon2-cffi` is now installed in CI (a dep enters CI only once a real test imports it). (issue #13 / PR #14.)

- 2026-05-22 — **Record/commit a `LESSONS.md` lesson at wrap-up *after* the PR actually merges (the Priority 1 merge step), NOT when moving the item to In Review.** A prior session committed the note-list lesson to `main` referencing "(#35/#36)" while PR #36 was still open — so at the next cold start `main`'s HEAD was a lesson commit that *looked* like the PR had merged, while `board_snapshot.md` and the live board both correctly showed #35 still In Review. ## Anti-patterns

- Seed lesson — **Do not write "editorial-pin" tests** that assert a doc/markdown list matches a code constant, AST-presence checks, or set-identity between prose and code. They never catch real bugs; they only fire on intentional human edits, creating a maintenance tax. (This is encoded as a hard rule in `autodev.md` → Priority 5B "Prohibited test patterns"; recorded here so the reasoning travels with the project. If cross-file drift ever causes a *real* bug, fix it with one CI script, not per-pair tests.)
